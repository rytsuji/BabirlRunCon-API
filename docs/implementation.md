# 初期版の仕様と制限

## 実装元

babirl250503 の babicmdjson.c、comfuncsjson.c、babicon.h、bi-tcp.c、bi-com.c、bbjson.c、bbxml.c と必要なヘッダーを csrc/babirl に同梱します。追加コードは csrc/binding.c と capture.h。Python の操作層と HTTP 層は runcon にあります。

build.py は上流ソースの main を除外し、ライブラリ用ソースを build/native に生成します。上流 C ファイル自体は変更していません。include/bi-common.h は macOS の union semun 再定義を回避する条件を追加したものです。共有ライブラリには古い common シンボルとの互換性のため -fcommon を使っています。

既存 CLI のシェル実行やプロセス停止処理は公開していません。API は固定の操作だけを受け付け、クライアントから接続先や任意コマンドをリクエストごとに注入できる入口はありません。

## getesevtnumber

元の babicmdjson にも getesevtnumber はあります。旧バインディングで公開していなかった操作を公開しました。元の JSON 版は可変長の受信を evtn[i] という1整数分の領域へ直接行います。一方、babicon 版は複数語の配列として受信します。babild が ES として動く場合などは実際に複数語が返ります。

本版は生成ソースで getevtn をチェック付きアダプターに差し替え、4..4096バイト、4の倍数の応答だけを受信します。

```json
{"lastevtn":[{"efn":0,"host":"frontend","name":"test","evtn":123,
              "raw_words":[123]}]}
```

先頭語を unsigned なイベント数 evtn として返します。複数語の応答は符号付きマーカーを含み得るため、全語を raw_words にも保持します。入れ子構造の意味付けまでは行いません。元の EF 順で取得し、いずれかの EF 取得が失敗したら全体をエラーにします。使用中（ex が有効かつ of が ON）の EF のみが対象です。

EF のホスト名は C 側でも IPv4 に名前解決します。ES のポート基準値は設定から指定でき、モックでは空きポートを使います。EB のポート変更と ES のポートは独立です。

## 状態・競合・失敗

Python のロックで、設定確認→変更→再取得の操作全体を直列化します。C 内部にも共有状態保護のロックがあります。読み取りも同じロックを使い、書き込み処理の途中に割り込みません。待ち合わせはキュー長制限なしのため、混雑時は応答が遅くなります。

起動は babirl_runcon.py から1 worker とします。複数 API プロセス・複数 API サーバーで同じ DAQ を制御するための分散ロックは未実装です。babicon など外部ツールによる同時操作も防げず、状態確認と実操作の間に外部操作が入る可能性があります。

既存 C のコマンドは成功でも0を返すものがあるため、関数戻り値だけで成功を判断しません。JSON の error を確認し、変更後は再取得します。設定は要求値との一致、開始・停止は Run 状態を確認します。複数設定の原子的更新・ロールバックはありません。

Stop は元の手順に従い、停止要求、状態待ち、保存Runの Ender 設定、RUN_CLOSE を行います。元の Stop が付加的に行う EF イベント数取得は省略しています。EF 数は専用 GET で明示的に取得してください。

接続・送受信は5秒単位のタイムアウト、ネイティブ呼び出しは約30秒を超えた後の通信境界で中断します。厳密な実時間上限ではなく、DNS の時間、ロック待ち、複数ネイティブ呼び出しを含むAPI全体はそれ以上になることがあります。HTTP クライアントが切断しても既に始まった操作は継続し得ます。自動再試行はしません。

## データ・互換性

通信は native-endian 整数と C 構造体のバイナリ転送です。DAQ とヘッダー・レイアウト・エンディアンが互換である必要があります。長さ不一致は検出しますが、同じサイズの ABI 不一致を全て検出できるものではありません。

runname は空白なしの1トークン、Run 名・Header・Ender は UTF-8 で79バイト以下。runnumber は0..2147483647。HTTP で事前検証します。Header の空文字クリアには対応しません。Run 情報内の日付文字列は既存 C が生成する DAQ API サーバー側のローカル時刻、observed_at は API が取得完了時に付ける UTC です。

C の stdout をプロセス全体でリダイレクトせず、ライブラリ内の printf だけを open_memstream に捕捉します。中断時は部分 JSON を破棄してエラーオブジェクトを作り直します。

元の babicon と JSON 版は関数名が共通でも挙動が異なることがあります。getebname は babicon にだけ存在する内部取得関数です。setscrname は JSON 版では未対応、setconfig は未実装と明示されています。この初期版で全 babicon 操作の互換を主張するものではありません。babinfo 向け操作、EF 設定変更、スケーラー設定、babimo、GUI は今回の範囲外です。

## 運用

同一サーバーの systemd 等で常駐化する場合も、仮想環境の Python、babirl_runcon.py、絶対パスの --config を指定して1プロセスだけ起動してください。常駐化のシステム設定はこの配布物では変更しません。

認証トークンは環境変数で指定します。設定例に秘密値は保存しません。トークン設定時は API エンドポイントに認証を要求します（自動 API ドキュメントの静的表示は認証対象外ですが、操作APIには認証が必要です）。既定は localhost 待受かつ変更禁止です。
